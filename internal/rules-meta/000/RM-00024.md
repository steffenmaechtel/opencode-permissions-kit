A single folder holding 100+ metas becomes an unnavigable wall in IDE
trees and file listings — the maintainer caps a folder at 100 files.
Sharding by the first three ID digits enforces exactly that cap while
keeping the location computable from the token alone — no
bookkeeping, no semantic mapping to maintain, and a rule moving
between files can never affect where its meta lives. Migrated while
the corpus was young (a pure `git mv`), because every later consumer
— index, audit, bookmarks — would have pinned the old paths.

Check: every meta file sits in the bucket matching its first three ID
digits; no bucket ever exceeds 100 files.

Source: maintainer decision 2026-10-15 (size cap: 100 files per
folder → shard depth 3).
