The rules audit enforces a closed world: a real RM ID occurs at
exactly three sites — as the trailing `(RM-NNNN)` ref at its rule
unit, as the `id:` line of its meta file, and as its generated row in
the rule-meta INDEX (the no-fake-findings pin,
`tests/unit/test-rules-meta.sh` pin 10, lanes a–c; the audit script
blocks on invariants 1–6 and 9 — 7–8 are report-only —
`scripts/rules-audit.sh`). Until
this rule existed, that invariant lived only inside the audit tooling:
agents writing NEW text (the .agents/skills pilot, issue #178) cited
rule keys as if they were ordinary stable references and doubled a key
mention inside a rule file — both caught red by the audit, both
requiring rework of already-written content. Citing by file and
section anchor keeps the reference readable for humans and agents that
never load the rules-meta system, and keeps ID search meaningful.

Check: `sh scripts/rules-audit.sh` and `sh tests/unit/test-rules-meta.sh`
stay green after any wave that adds prose mentioning rules. Pin 10
lane c scans the living tree's `*.md`, `*.sh`, `*.py` and `*.yml`
files only (other extensions — e.g. the frozen JSON corpus under
`internal/reviews-meta/` — are not scanned) and fails on any real ID
outside a rule unit's trailing ref. Exemptions beyond the four corpus
sets (`internal/rules-meta/` itself, the generated review indexes
(`INDEX.md`, `legacy-index.md`), the frozen case folders
(`internal/reviews/<d>/<d>/<d>/<d>/pr-*/`), `internal/records/_archive/`):
the SCOPE_FILES themselves (lane a checks those) and `RM-9xxx` demo
IDs. Living files under `internal/reviews/` (the README) are in
scope. The INDEX row — the third site — is machine-generated
(regenerated by the audit, pinned by
`tests/unit/test-rules-index-parity.sh`), which is why
`internal/rules-meta/` sits in lane c's exemption list.

Source: session incident 2026-10-23 (skills pilot wave, issue #178);
