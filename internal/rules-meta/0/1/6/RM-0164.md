An apostrophe inside a single-quoted sh -c worker string terminates
the literal when the worker parses — the remainder becomes garbage.
Probes (pr-00586 round a A2) split the shapes: an unbalanced
apostrophe count fails sh -n on the outer file outright, but a
balanced pair concatenates into a worker that sh -n accepts AND that
runs rc 0 while silently dropping every command behind the comment —
only grepping worker-string comments for apostrophes discriminates
before runtime. The pr-00568 wave broke ddev-handover.sh twice this
way (comments carrying abort's).

Check: new or edited comment text inside single-quoted worker strings
greps apostrophe-free — the only pre-runtime discriminator (sh -n
misses the balanced shape, execution misses the silent no-op).

Source: issue #578 §3; files/opencode-permissions-kit-lib/sh/ddev-handover.sh.
