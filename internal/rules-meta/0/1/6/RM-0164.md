An apostrophe inside a single-quoted sh -c worker string terminates
the literal when the worker parses — the remainder becomes garbage
that fails parsing of the string content. sh -n on the OUTER file
passes, because the worker string is opaque until the worker
executes. The pr-00568 wave broke ddev-handover.sh twice this way
(comments carrying abort's); only the devowned-flag helper sourcing
the lib (rc 2, expecting a closing brace) surfaced it.
Check: new or edited comment text inside single-quoted worker strings
greps apostrophe-free, and the touched file is verified by sourcing
it, not by sh -n.
Source: issue #578 §3; files/opencode-permissions-kit-lib/sh/ddev-handover.sh.
