POSIX makes redirection errors on special builtins (dot, colon)
fatal in non-interactive shells; dash implements that, bash-as-sh
instead continues with a non-zero rc — a bare colon-with-/dev/tty
probe kills a dash script rather than returning an rc to branch on.
The config.sh M1 guard hit this live (pr-00568 wave a): running the
probe inside a subshell turns the fatality into a branchable rc.
Check: run a subshell-wrapped colon probe against an unopenable
/dev/tty under dash with no controlling terminal — it prints an rc,
it does not die.
Source: issue #575 §3; files/opencode-permissions-kit-lib/management/config.sh.
