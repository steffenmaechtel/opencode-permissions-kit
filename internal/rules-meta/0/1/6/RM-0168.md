Re-deriving a make target's reach from its direct prerequisites
reads the Makefile, not the trees the invoked suites walk — and the
unit lane contains repo-root-wide recursive scans. The live case:
scripts/release.sh (step 3.5/5) runs make test check-version, no e2e
prerequisite anywhere in the chain, and the rules-meta parity
suite's lane c greps the whole repo root, reaching tests/e2e/dumps/
— container-created files, container-UID-owned, mode 700 — so the
maintainer's warm-tree make test died rc 2 on permission denied
(#587), a reach invisible in make release's prerequisite chain.
Verdicts naming a make target enumerate what its suites recursively
traverse, not only what the target depends on.
Check: a verdict about a make target's reach survives a run with the
tree its scans walk actually present (e.g. an e2e dumps directory).
Source: issue #588 §3; issue #587.
