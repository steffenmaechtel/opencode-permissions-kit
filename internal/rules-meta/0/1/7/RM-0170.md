Round comments are drafted before they are posted, and natural
drafting writes derivable fields — the provenance timestamp, the
marker severity counts — from memory into the draft. Two live
incidents: pr-00589 round b posted an estimated timestamp (12:16Z
prose over a 12:13:26Z GitHub stamp, disclosed in that case's closing
summary), and pr-00593 round a's draft marker claimed a HIGH finding
over a 0-HIGH round, caught only by re-reading the draft before
posting. The marker is the durable machine-readable record of the
loop — the release gate resolves it over the PR timeline — and
nothing re-checks it after posting, so a wrong count corrupts the
record silently.
Check: the newest round comments' marker counts match their posted
findings tables.
