POSIX parameter expansion substitutes :- on empty values as well as
unset ones, so an override passed as an empty string leaves the
default in force instead of overriding it. The pr-00590 m3 harness
passed ROOT_EQUIV_SOCKS as an empty string believing it replaced the
socket list; the section read it back through :- with the real host
list as default, and the arm silently scanned ambient WSL mounts — a
false red on first-class platforms, caught only by review (round a
T1). The fixed site documents the trap in place (the m3 comment in
tests/unit/test-status.sh); this rule generalizes the shape to every
harness env override.
Check: grep the suites for empty-string env overrides feeding :- consumers.
