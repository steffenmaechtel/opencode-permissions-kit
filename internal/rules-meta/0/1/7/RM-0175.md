posted.log is not a log-keeping nicety: it is the substrate the
hard seam checks mechanically (before the first fix commit of a
wave, the session re-reads it for the current round's comment URL —
no entry, no fix). In the pr-00605 session, ad-hoc echo scaffolding
around the posting command twice appended a fabricated second URL
(an unrelated comment id reconstructed from a follow-up api call,
then a GraphQL node id from a GraphQL-vs-REST mixup), each needing
a manual rewrite of the log. The posting command's own stdout is
the authoritative URL and needs no reconstruction at all.
Check: a fresh round's posted.log holds exactly one line per posted
comment, each line the gh pr comment stdout URL.
