Shipped code runs as `curl | sudo bash` on user machines where
$TMPDIR can be unset, read-only or full — a bare `$(mktemp)` death
there aborts with the shell's generic message and the user cannot
tell what stopped. The guard message is the only channel that reaches
the user: the pipe already owns stdin, and a silent return leaves a
dead terminal. Every shipped fetcher already guards its mktemp
with a named cause (the #364 class: files/install.sh and
management/update.sh SHA256SUMS fetches, bin/setup-container-backend
get.docker.com fetch), but the standard lived only as sibling shape
until 2026-11-15 — new code in tests/e2e followed its local sibling
instead and the divergence surfaced as a review finding (PR #532
round a S1, disposition deliberately-not-done — sibling-consistent,
the whole-file guard wave scoped out; no written rule named the
boundary either).

Check: grep mktemp receivers under files/ for a named-cause failure
arm — any of the house shapes counts (`|| {` with an echo naming the
consequence, an `if !` branch with message, `|| die "…"`, a
degrade-loud fallback); bare `|| return 1` arms (the
sh/ddev-migrate.sh:170 shape) are the class debt, not conformance.
e2e/test scaffolding keeps its lighter sibling shape by the scoped
rule.

Source: issue #535 §2 (end-of-session reflection over PR #532);
related code-class work orders #431, #376.
