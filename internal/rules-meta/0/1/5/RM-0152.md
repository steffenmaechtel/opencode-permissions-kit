The repo's only fence-aware tooling is the rules-audit unit parser,
and its fence regex anchors at column 0 — an indented fence inside a
rule bullet is invisible to it, so structural damage there has no
gate: #526's C4 fix deleted a template fence's opening line in
review-concept.md and every suite stayed green; the maintainer's read
caught it. Round a B2 of #526 had recorded the parser blindness as an
INFO footnote without connecting it to the missing well-formedness
guard. The line-length ratchet is NOT a counterexample and not
fence-aware at all: test-line-length.sh carries zero fence tokens and
measures indented lines like any other (verified 2026-11-15, PR #544
round a C3 — issue #528 §1's contrary claim was copied into the first
draft of this meta, a live instance of the measure-don't-copy rule).

Check: delete an indented fence's opening line in an agent/ rule file
and run the full suite — nothing reds.
