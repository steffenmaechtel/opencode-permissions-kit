POSIX pipelines fork every member: a shell variable first assigned
inside a pipeline member is gone when the pipeline ends, while a
variable assigned in the main shell before the pipeline is visible
inside every member (probed 2026-11-21: the fork-written cache read
unset after the pipeline, the main-shell cache was inherited). A
once-per-run probe cache therefore works only when the first probe
runs in the main shell — PR #710 round b D2 measured the alternative
live: every tee call site re-probed and re-warned because each sits
in a pipeline fork. fs-baseline.sh's comment block documents the
same mechanism for its two-pass shape.

Check: shipped tees cache their probe verdict in main-shell state
reached before the first pipeline (the `_py_checked` guards); the
degradation warn appears once per run, not once per call site.

Source: issue #714 incident 1 (D2); fs-baseline.sh comment block.
