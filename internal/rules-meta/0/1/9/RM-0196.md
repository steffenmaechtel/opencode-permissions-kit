PR #710's rebuilt probe lost its diagnostics twice in review before
this shape settled: the diagnostic rerun carried `2>&1`, discarding
the very stderr it existed to show (round b D1), and the first draft
had no plain passthrough to degrade to at all (round a B1). The
shipped reference spellings differ harmlessly: status-core and
git-heal-core swallow only stdout on the first probe so the
interpreter's stderr flows; fs-baseline reruns the failing probe
with stderr visible; all three degrade to `cat` with one warn line
naming the loss — the stream keeps its data and loses only the live
counter.

Check: the broken-interpreter arm of each pin suite asserts BOTH the
warn line and an intact passthrough stream (the data rows still
arrive).
