An e2e arm observes a git command's failure shape through the
command's own output channels; a blanket `>/dev/null 2>&1` written
to swallow one expected rc (a conflict) swallows every unexpected
death the same way. The #678 conflict-state arm silenced its merge
to hide the expected conflict rc 1 — and the identity refusal
behind it (rc 128) went into the same hole, leaving downstream
assertions to fail silently with "no merge to abort" as the only
symptom (issue #686 item 1). The silencing scope, not the conflict,
was the bug.

Check: e2e arms that redirect a git command's output keep the
failure mode they observe diagnosable — output lands in a log file
or the swallow is scoped to the expected rc.

Source: issue #686 (PR #684 session, 2026-11-19/20).
