`git checkout -B <branch>` prunes a worktree directory that only
holds the OTHER branch's tracked files — the directory goes empty
and git removes it, so a fixed-path write into it afterwards dies
"Directory nonexistent". Hit twice in one #678 wave (measurement
harness dev.sh p2, then again in the e2e arms) because the instinct
is one `mkdir -p` at setup time; the pruning happens at every
switch. Probed 2026-11-20 in scratch: dir gone after the switch,
`mkdir -p` directly after it restores the arm.

Check: topology-construction arms in tests/e2e carry `mkdir -p`
after every `checkout -B`, not once at setup.

Source: issue #686 (PR #684 session, 2026-11-19/20).
