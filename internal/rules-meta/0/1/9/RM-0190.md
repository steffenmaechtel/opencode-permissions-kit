The e2e suites run git as container users that carry no global git
identity — the suite never configures one, and the pre-existing arms
never needed it (checkout/add/reset create no commits). git refuses
commit-creating commands without a committer identity, rc 128 with
"Committer identity unknown" on stderr — a refusal whose visibility
dies inside a blanket output silencing, so the #678 fix wave's
identity-less merge left three arms red with zero stderr evidence
until a container repro un-silenced the merge (issue #686 item 1).
Probed
2026-11-20 in scratch: identity-less merge dies rc 128, inline
-c identity passes.

Check: every e2e arm whose git command creates commits passes
user.email/user.name inline — grep the arms for merge/cherry-pick/
rebase/am calls lacking -c user.email.
