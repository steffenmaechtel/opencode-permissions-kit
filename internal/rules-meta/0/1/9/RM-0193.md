Fixture state from one e2e arm leaks into every later git-writing
arm of the same repo: files left STAGED by an earlier section make a
later merge refuse with "would be overwritten by merge" wherever the
merge touches the same path — the #678 slim RL2b block ended with a
bare `git add`, its `agent-file.txt` stayed staged, and the merge
arm behind it refused on a fixture the merge never asked for (issue
#686 item 3). The refusal needs path overlap (probed 2026-11-20: a
staged new file unrelated to the merge target passes) — which is
exactly why the bleed feels intermittent.

Check: e2e arms that stage files end with the unstaging reset or an
explicit cleanup, unless a later arm in the same repo consumes the
staged state on purpose.

Source: issue #686 (PR #684 session, 2026-11-19 to -20).
