Hard ACL denies broke the kit's second job: mirroring
`*settings.php: deny` into a `u:opencode:---` ACL made the TYPO3 web
container unable to boot (it must read `config/system/settings.php`),
`.ddev/commands/<svc>/README.txt` needed an `ask` carve-out for the
same reason, and a root-powered transaction helper existed only to
juggle those collisions. The soft-only decision removed the deny layer
wholesale; any re-introduction of OS-level denies re-opens that
defect class. Inside containers with bind mounts file reads are
unrestricted anyway, so the OS layer never added security there — it
only broke ddev.

Check: shipped scripts carry no `setfacl` deny entries; status.sh
keeps its leftover-deny scan.
