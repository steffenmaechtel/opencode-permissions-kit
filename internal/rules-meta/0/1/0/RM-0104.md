Issue #100: kit 0.0.36 wrote an invalid hyphen-named section into
`/etc/wsl.conf`, and on WSL ≤ 2.9.12 the parser aborted the whole
file — silently disabling every WSL setting the user had, including
systemd. The damage surfaced only after the next WSL restart
(`wsl --shutdown` from a Windows PowerShell, then starting the
distro again): wsl.conf takes effect at instance start, so nothing
at install or write time pointed at the broken section. `/etc/wsl.conf`
is user-owned system configuration with boot-time effect on the
entire distro; a yes/no prompt mid-install is not informed consent
for that class of change, and one of the two legacy write paths had
no prompt at all. The sanctioned exception only removes kit-owned
bytes (the broken legacy section) to restore parseability — it never
writes content.

Check: the only wsl.conf writer stays `opk wsl-add-opencode-1-fix` on
explicit invocation; update.sh only strips the legacy section.

Source: internal/records/wsl-conf-consent.md; issue #100.
