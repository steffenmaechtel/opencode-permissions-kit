A release is maintainer-scripted: the VERSION bump lands on master via
its own release PR, then `make release` (scripts/release.sh) verifies
the preconditions, tags the bare `x.y.z`, and fast-forwards the stable
mirror. Tags are user-installable pins (`KIT_BRANCH=0.0.17`), so a
version bumped inside a feature PR advertises a release that was never
cut and breaks the bump-PR trace; `make check-version` additionally
ties the stamp to the in-code `KIT_BRANCH` defaults. Version bumps are
release handling, not feature work.

Check: `VERSION` changes only in `release/*` PRs; the tag list and
the VERSION file agree.

Source: CONTRIBUTING.md, Making a release; internal/process/
release-handling.md (Option B procedure).
