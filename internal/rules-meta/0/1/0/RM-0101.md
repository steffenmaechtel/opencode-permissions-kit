Install and update fetch every kit file by explicit path from
raw.githubusercontent (the per-file `KIT_FILES` lists in
files/install.sh and the deployed update.sh) — a renamed script is a
404 on the next `opk update` for every existing install, because the
already-deployed updater keeps requesting the old name from the new
ref. Inside the repo the same names are pinned by the Makefile, the
CI workflows, and the docs, so a rename severs references in four
places at once while looking like a local cleanup.

Check: `KIT_FILES`, the Makefile, tests, and docs reference the same
`files/` paths.

Source: internal/process/release-handling.md §2 (per-file fetch);
files/install.sh (KIT_FILES).
