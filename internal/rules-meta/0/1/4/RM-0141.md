The audit enforces exactly one ref per rule unit in every ACTIVE
section (rules-audit.sh invariants 1 and 3): a doc wave that adds a
bullet without its meta makes the rules-meta suite red, and a wave
that ships a whole new conventions section without listing it in
ACTIVE_SECTIONS leaves that section's rules untracked — the exact
gap the record's pilot-scope decision closed for the first four
agent/ files. Issue #528 (item 3) shows the cost of discovering the
suite red only at the full gate.

The bucket clause: the audit's second invariant resolves every ref
to internal/rules-meta/<d1>/<d2>/<d3>/RM-xxxx.md by the ref's first
three ID digits, so a meta written into the previous bucket — the
natural move at a boundary is copying an id-neighbor, and every
neighbor sits across it — reddens with a no-meta-at path; first live
case: the 017x-to-018x boundary crossing in issue #623 item 2, one
gate cycle paid.

Check: add a ref-less bullet to any ACTIVE section and the
rules-meta suite fails; add a new section to conventions.md without
its ACTIVE_SECTIONS line and its bullets pass unaudited.

Source: docs-loop design 2026-11-15 (founding backlog #523–#538);
issue #528 item 3; issue #623 item 2.
