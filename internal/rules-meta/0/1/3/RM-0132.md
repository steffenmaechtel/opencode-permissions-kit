Context data from the same pilot: implementer-session reviews
compounded to 303k context over six cases while fresh single-PR
review sessions stayed flat at 83–110k. A flash axis costs the same
wall-clock time as the session reviewing directly (subagents run in
parallel; main waits either way), so the uniform
review-is-always-a-subagent rule needs no exception in the no-solo
rule. PR #320 ran the loop with a main-direct round (a reviewers:0
marker) — kept as precedent for the LOOP shape, not the review-pass
shape.

Amended twice 2026-10-31 (same PR): a first correction over-hardened
the rule (implementer NEVER runs a loop — the literal reading of
decision 1's summary line). Corrected to the maintainer's operative
reading: a SINGLE-case commission keeps the single-session shape
(Session MAIN implements and runs the loop, pilot's 4× MED shape —
the pre-v2 batch rhythm of the issue body died instead); a BATCH
commission splits the roles — implementer only implements, one
fresh review session per PR (rolling, max 2 parallel).

Check: batch PRs' markers carry session "fresh" and
reviewers ≥ 1 in every round, one review session per PR; single-case
loops run in the implementer session with subagent review passes.

Source: issue #324 (§4.3; decision 1 — operative reading per
maintainer clarification 2026-10-31: single case = implementer runs
the loop, batch = implement-only + fresh sessions per PR).
