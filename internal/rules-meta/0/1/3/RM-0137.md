The #283 leak class (a scratch receiver outside the trap's operand
list leaked on a set -e abort or a signal) was fixed suite by suite
for three waves: each widening re-listed every receiver by hand, and
test-status's `_trap_cleanup` had grown to nine operands with a
comment explaining why they no longer fit one line. Issue #395's
registry ends the class structurally instead: `work_new` /
`work_new_file` create AND register a receiver in one step (no window
between creation and registration), `work_register` /
`work_register_var` migrate pre-existing receivers, and one central
EXIT INT TERM trap in `tests/unit/lib/harness.sh` iterates the
per-process registry file (a FILE so registrations from command
substitution reach the parent's trap).

Check: converted suites carry no trap statement of their own — a
local trap replaces the harness trap and silently disarms the
registry, the very class from the other side; the sandbox floor
(test-sandbox-policy.sh check 4) flags that mix, and its self-probes
pin the detection. A suite mixing both shapes is the ungated fact
returning.

Source: issue #395 (spike PR follows this meta), closing the #283
class the acceptance section of #395 demands.
