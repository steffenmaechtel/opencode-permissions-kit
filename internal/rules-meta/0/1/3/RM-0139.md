work" (2026-10) did not stop the class: PR #441 round b D1
(2026-11-10, HIGH, fix-induced) pushed a pin WITHOUT its
recursion-break marker. Timeline: the fix wave was committed and the
first sabotage cycle ran correctly; then a fresh edit (the marker)
landed uncommitted in the working tree; the SECOND cycle's `git
checkout --` restore reset the file to the index — the unstaged marker
edit was silently wiped; the rc-based restore check passed (rc 0 holds
for the pre-fix and post-fix version alike, the wipe is invisible to
rc by construction); an `--amend` that committed nothing new sealed
the loss. Only the fresh round-b reviewer's grep caught it (zero hits
in the tree vs the PR body's claim). The maintainer estimates the loss
shape at roughly every third session.

preparation (not a per-cycle invariant), it demanded no
content-based restore verification, and it named no amend indicator.

tree; restore verification greps the construct the fix introduced; an
amend that commits nothing new is a loud signal, not a no-op.

Check: sabotage runs record the securing step per cycle; restores are
content-verified; no post-sabotage restore lands on a dirty tree.
