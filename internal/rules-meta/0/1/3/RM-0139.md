The AGENTS.md Testing rule "Sabotage-verify only against secured
work" (2026-10) did not stop the class: PR #441 round b D1
(2026-11-10, HIGH, fix-induced) pushed a pin WITHOUT its
recursion-break marker. Timeline: the fix wave was committed and the
first sabotage cycle ran correctly; then a fresh edit (the marker)
landed uncommitted in the working tree; the SECOND cycle's `git
checkout --` restore reset the file to the index — the unstaged marker
edit was silently wiped; the rc-based restore check passed (rc 0 holds
for the pre-fix and post-fix version alike, the wipe is invisible to
rc by construction); an `--amend` that committed nothing new sealed
the loss. Only the fresh round-b reviewer's grep caught it (zero hits
in the tree vs the PR body's claim). The maintainer estimates the loss
shape at roughly every third session.

Recurrence after the 2026-11-10 sharpening (2026-11-16, PR #568 round
c Z3): a quick fix landed mid-cycle in the SAME file the cycle
sabotaged — a state where neither securing move applies (committing
bakes the sabotage into the commit; `git stash` mixes fix and sabotage
in one stash). The `git restore` wiped the fix; it was re-applied and
content-verified, the per-cycle rule was violated once with no reader
running.

Three gaps in the 2026-10 wording: it read as one-time phase
preparation (not a per-cycle invariant), it demanded no
content-based restore verification, and it named no amend indicator.

Expected effect: every sabotage cycle starts from a verified-clean
tree; restore verification greps the construct the fix introduced; an
amend that commits nothing new is a loud signal, not a no-op; a
mid-cycle quick fix is secured by the unconditional pre-restore copy
(the copy is the securing step — no mid-cycle gate + commit owed).

Check: sabotage runs record the securing step per cycle; restores are
content-verified; no post-sabotage restore lands on a dirty tree;
mid-cycle quick-fix cycles record the pre-restore copy, and a recovery
re-applies only the fix hunks from it.

Source: PR #441 round b D1 (verified against the PR timeline; the
corrective wave's fix commit b992237b); maintainer directive 2026-11-10
(sharpen AGENTS.md Testing + restate in the review pages); AGENTS.md
Testing sharpened in the same wave.
