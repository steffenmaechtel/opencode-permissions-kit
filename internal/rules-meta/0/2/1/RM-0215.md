Closing keywords name issues of the repository they are written in
unless spelled for another repository, and GitHub documents a
cross-repository form (Linking a pull request to an issue,
docs.github.com); the first draft of issue #755 assumed the keywords
do not reach across repositories at all, a claim its design never
verified. The cutover itself supplied that observation: PR #769's
merge (2026-11-23T23:36:04Z) closed its check issue
opk-agent-feedback#1 by the merge itself — the issue payload's
closed_at reads 23:36:07Z, the timeline's closed event 23:36:08Z
(GitHub's two API surfaces differ by one second) — the
cross-repository closing keyword works as documented. Two trackers
still need the reference spelled out and a backstop that does not
depend on platform behavior: the disposition comment
is the record either way, and an issue the merge left open is
closed at the next trigger check.

Check: After a cutover-era merge, compare the feedback issue's state
with the keyword its landing PR carried; a merge that left it open is
the backstop's case.

Source: issue #755; GitHub docs, Linking a pull request to an issue.
