Issue numbers are per repository, and the docs-loop cutover moved new
reflection topics to a second tracker (issue #755): a bare number in
new rule text resolves inside this repository, where the same number
is an unrelated issue — a silent wrong pointer. GitHub creates
autolinked references in conversations only, not in repository files
(Autolinked references and URLs, docs.github.com), so the short form
is a grep key by design, not a link.

Check: A tree-wide grep for the short form finds the feedback
citations; a bare number beside a reflection claim written after the
cutover is a miss.
