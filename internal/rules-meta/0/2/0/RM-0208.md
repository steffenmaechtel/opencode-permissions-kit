An existence assert through a symlink follows the link to its
target — probed 2026-11-22: test -e through a link to
/etc/sudoers.d/README reads true where that host path exists, false
through a dangling link. A fixture that references a host path it
never executes therefore still imports host filesystem state: the
#748 foreign-symlink pin was green on the contributor host (target
present) and red on the CI runner (target absent, unit lane red on
ef5be2da, run 45060522456) — the literal was inert in the executed
sense, the assert was not. The sandbox rule's executed-path leg
cannot see this channel; referenced paths need their own leg.

Check: fixtures are grepped for referenced non-scratch paths — link
targets, grep needle inputs, comparison baselines — and each is
either scratch-owned or the assert is dropped.

Source: issue #749 incident 2 (PR #746 round b D5, #748).
