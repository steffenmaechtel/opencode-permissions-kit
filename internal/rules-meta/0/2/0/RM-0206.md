The gh CLI serves a run's outcome as two separate fields: status
(completed or in progress) and conclusion (success, failure,
cancelled, and more). A watch loop that counts completed entries
reads the first field and ignores the second — over two
completed-but-failed runs it reports done, and a closing summary
built on it proceeds on a red push. Live shape on this repository
(2026-11-22): run ids 45065019566 and 45065019491 on sha 14fae519
are completed with conclusion cancelled — a completed-count
predicate counts them as done. The pr-00732 closing-phase watch
built exactly that predicate; only the maintainer's cross-check
caught it before the session proceeded.

Check: a CI-watch loop in session scratch or transcript greps a
per-run conclusion of success keyed on the current commit's run
identity, never a count of completed statuses.

Source: issue #743 (pr-00732 closing phase).
