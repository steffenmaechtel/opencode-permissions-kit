Shell functions persist across invocations within one process —
probed in dash 2026-11-22: a stub defined in invocation 1 satisfies
command -v in invocation 2 of the same shell, so a presence check
proves the function exists, never where its definition came from
(an earlier invocation, an export -f import under bash, or a sourced
vintage all satisfy it identically). The never-shadow fail-safe in
the update browser-bridge carried a marker whose precondition was a
command -v presence check placed after the sourcing loop — the
persisted rc-0 stub from a candidate-less invocation satisfied the
precondition in the next invocation, arming exactly the churn state
the marker existed to prevent (PR #746 round b D1 over round a's B1
fix; the fix unsets the function at entry so every invocation
re-derives the probe from its own sourcing).

Check: a stub-or-real distinction keys on an invocation-scoped unset
-f reset or a definition-site marker set by the sourced file, never
on bare command -v presence.

Source: issue #749 incident 3 (PR #746 round b D1, fix 53364ca9).
