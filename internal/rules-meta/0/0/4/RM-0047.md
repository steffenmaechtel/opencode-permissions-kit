Commit b14a198 is the proof by failure: the e2e fake-ddev was faithful
to every call and output the tests asserted, yet the production
binary drained stdin inside the migrate loop and broke exports for
real users — the fake was blind exactly where nothing asserted
behavior. A double that replicates only the asserted observables
inherits the tests' blind spots; the unasserted side effects (stdin
consumption, tty probing) are where production diverges. The rule
closes that structurally: every observable the code under test can
touch gets replicated, and each real-binary surprise becomes double
behavior plus a regression test, so the fidelity cannot silently
decay.

Check: doubles in unit/e2e suites replicate the stdio side effects of
their real binaries; each taught behavior carries a regression test.

Source: commit b14a198.
