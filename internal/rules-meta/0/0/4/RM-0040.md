Malformed-input handling has two consumers with opposite needs.
Maintainer automation (advisory-watch in CI) runs unattended: skipping
a malformed record with a warning and exiting non-zero turns the skip
into a red run someone sees — failing soft there deletes findings
silently. The wrapper's hot path is the opposite: it starts a user's
session, and an unavailable optional check must not keep the session
from starting, so it degrades and continues. The rule splits by
consumer, not by convenience.

Check: advisory-watch exits non-zero on malformed records; the
wrapper hot path logs-and-continues when a check is unavailable.

Source: scripts/advisory-watch.sh (die → exit 1).
