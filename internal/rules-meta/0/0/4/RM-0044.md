An unset-or-empty variable degenerates only when a literal suffix
follows it: `rm -rf "$WORK"/sub` becomes `rm -rf /sub` — a real,
destructive path — while the pure-variable form degenerates to an
empty operand, a verified no-op. The `:?` guard
(`rm -rf "${WORK:?}/sub"`) aborts with the variable name instead. The
check is spelling-proof because every quoting variant degenerates
identically on empty; it scans the unit suites and e2e helper scripts
mechanically, and shipped code holds the same standard by review.

Check: no unguarded var+suffix `rm` in unit suites, e2e helpers, or
shipped scripts.

The prose clause: the statement scoping is chain-based, not a
parse — an unquoted semicolon or redirect boundary breaks the chain,
but every token inside the span is walked, so message text on a live
line can match the same way rm statement operands do — the #601
chmod arm's fail message carried the literal word rm a few
space-separated tokens before a quoted var-plus-suffix literal and
reddened check 3 (PR #628, issue #630); a reworded message (say
remove) sits outside the grammar by construction, probed against the
suite's own pattern.

Source: finding 2026-10-06; issue #630.
