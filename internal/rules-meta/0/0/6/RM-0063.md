In pr-00189 the implementing and reviewing snapshots carried header
labels identical in shape, so the same-session fact was unauditable
from the artifacts alone — it surfaced in maintainer chat (#189 c
C5). The metadata exists to make freshness verifiable after the
fact: which contexts ran which pass must be readable from the case's
own record, not from memory. In the PR-native era that record is the
round comment's metadata block (reviewers with model and axes,
curator, verifiers, tier — plus track, mode and session since #334).

Check: round comments carry the reviewers/curator/verifiers metadata
that distinguishes consecutive passes; deviations are visible from
the timeline alone.
