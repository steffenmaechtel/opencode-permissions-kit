When a round's session ends is a steering decision: the maintainer's
process (internal/process/review.md, "start a fresh session per
review round") owns the pause, because the committed snapshot between
rounds is their visibility window. The pause is also the maintainer's
window to clarify open points — with the USER, upstream, or the
resolution — before the next round's scope is fixed; once the next
session starts, its scope is already loaded. An agent that chains the
next session itself would consume both windows and start reviewing
before the maintainer has read what the last round found.
