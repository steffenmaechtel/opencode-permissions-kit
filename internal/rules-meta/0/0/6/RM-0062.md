The two constraints the rotation must not weaken both predate it:
the hard seam (snapshot committed before any fix, 0.0.42d) and the
maintainer go before the fix wave (reviews README, Process). The
rotation moves fix application INTO the reviewing session — the rule
pins that this move changes who applies the fixes, never when they
may start.

Check: rotation-era cases still show snapshot commit → maintainer go
→ fix commits, in that order.
