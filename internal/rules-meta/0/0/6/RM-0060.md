pr-00189 snapshot b reviewed its own fix wave inside the implementing
session: the header carried only the usual "house session" label, and
the same-session fact surfaced in maintainer chat, never in the
snapshot (#189 c C5). The author's context carries its blind spots
into the review of the fix. The PR-native era buys the same
protection with different mechanics: one Session MAIN runs the case,
and every review/verification pass is a fresh-context subagent, so
the loaded authoring context never reviews its own fixes.

Expected effect: fix-induced regressions and commit-vs-claim gaps
get read without the implementing context's justifications loaded.

Check: every review pass names fresh subagent reviewers/verifiers in
the round comment's metadata; no pass ran main-solo.

Source: internal/records/review-calibration.md, "Session-rotation
origin (pr-00189)"; the pilot retrospectives on #278.
