Report commands are consumed by cron jobs and systemd timers that
must not parse human-readable stdout — the verdict has to travel in
the one channel they natively read: the exit code. `opk status` maps
`0` all green, `1` alert(s), `2` warning(s) only, `64` usage error
(EX_USAGE), documented in the status.sh header. The mapping is an
external contract: changing a value breaks timers silently, which is
why usage errors took the sysexits value instead of a fourth ad-hoc
number.

Check: status.sh exits 0/1/2/64 per its header comment; no report
command invents additional verdict codes.

Source: management/status.sh header ("cron/timer friendly").
