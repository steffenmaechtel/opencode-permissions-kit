A y/n confirmation and a free-text prompt are different speech acts:
one offers a default decision, the other accepts arbitrary text. If
both rendered the same `[y/N]` shape, a glancing user would answer y
or n where the script expects typed text — or miss that typing is
possible at all. `ui.sh` therefore renders `ui_ask` as
`[default] >`: default in brackets, `>` as the type-here marker,
deliberately unlike the confirmation picture. The distinction is
per-interface, not per-script.

Check: every free-text prompt renders `[default] >`; no free-text
helper renders a y/N suffix.

Source: files/opencode-permissions-kit-lib/sh/ui.sh (ui_ask).
