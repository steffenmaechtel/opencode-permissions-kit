GitHub allocates PR numbers at creation time, so a draft PR's number
exists before any review work runs. Keying the case folder on that
number makes folder-name collisions between parallel features
impossible by construction; any post-hoc key (subject, date, branch
name) lets two features race for the same path.

Check: every case folder under internal/reviews/ carries its
birth-PR number and no two cases share a folder.
