The fake-ddev blind spot was structural: a fake that never reads
stdin means no test can catch a stdin-draining regression, however
many run against it. Every new fake or shim therefore replicates the
real binary's stdio behavior (consumption, tty probing) from day one,
plus a contract/regression test that fails if the double regresses or
the real binary changes — the operational form of the rule "a double
must replicate every observable behavior the code under test can
touch".

Check: new doubles in tests/ carry the stdio behavior and a contract
test.
