Codified in the 0.0.42d session after the maintainer asked for the
snapshot first; carried into the PR-native era as the posted-comment
seam. Both readings of the seam are violated by a late record: the
maintainer's visibility window closes (findings are no longer
inspectable while nothing has been done about them), and a fix
applied mid-verification changes the very tree the remaining
findings are verified against.

Check: in every case, the round comment's posted timestamp predates
its round's first fix commit.

Amended 2026-11-07 (the #407 incident): in a long implementer
session, rounds b–e were posted as one batch AFTER their fixes
(fix commits 22:37–22:49Z, comments 22:57:21–25Z, disclosed there as
a process deviation; round a had kept the seam — the maintainer
steered #399 back on seam in time). Root cause: the seam lived as
prose the session must remember; the skill choreographed the review
pass but not the transition into the fix wave. Mechanical form
added: before the first fix commit of a wave, the case scratch
`posted.log` must contain the current round's comment URL — no
entry, no fix. Rule text (review-concept.md) and the skill's
§7 step 5 swept in the same change.

Source: internal/records/review-calibration.md, "Hard-seam origin
(0.0.42d)".
