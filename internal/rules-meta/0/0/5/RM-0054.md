The `ddev()` shell function and the `BASH_ENV` hook exist only in
shells that loaded the developer's rc files — unit and e2e source the
function directly, so the fresh-login path of a real user is never
exercised by them. Vendor `runTests.sh` under `#!/bin/sh`, cronjobs
and IDE tasks ran real ddev as the wrong user (troubleshooting entry;
original transport issues #18). Covering the class requires spawning
real login/interactive shells (`bash -lic`, `su - <user> -c`), not
more sourcing.

Check: rc-installed behavior has a fresh-login-shell check in e2e,
not only sourced-function unit tests.

Source: issues #18 (original transport reports).
