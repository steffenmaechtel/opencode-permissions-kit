Browser launches and the Windows hosts file are interactive-only
surfaces — no CI environment can assert them honestly, and a test
that pretends to produces a vacuous green (the test-vacuous class).
e2e-ddev therefore asserts the container-side half and documents the
Windows side as a non-goal; the assertion that CAN run honestly is
the one worth having.

Check: e2e asserts the container-side halves of interactive surfaces;
the non-goals stay documented.
