Under `curl | bash`, stdin *is* the script stream — a prompt reading
stdin would consume the installer itself; that is why ui.sh prompts
read from `/dev/tty`, never stdin. The same class runs the other
direction in tests: with piped stdin a `read` either gets EOF or eats
test data, so prompt flows can only be tested under a PTY.

Check: ui.sh question helpers read `/dev/tty`; no shipped prompt
reads bare stdin.

Source: files/opencode-permissions-kit-lib/sh/ui.sh.
