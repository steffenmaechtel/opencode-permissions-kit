Issues (`#158`) and review findings (`0.0.42e C1`) are already cited
inline; the `RM-` prefix keeps tokens unambiguous at any width. Four
digits: the long-term estimate is ~500 rules and numbers are never
recycled — lifetime consumption stays an order of magnitude below the
9,999 ceiling. The decisive bonus: at four digits, a ≤10-per-node
storage structure needs only three levels, one digit per level. The
original 5-digit PR-width analogy was traded for exactly that.
Allocation is chronological (next free number), and the first number
stays reserved for the main rule itself.

Check: `grep -rnE 'RM-[0-9]{5}'` finds nothing; every 4-digit
citation resolves to exactly one meta.

Source: maintainer decision 2026-10-16 (width 5 → 4 — buys one
storage level; re-padded while the migration was still cheap).
