The prototype settled it: a committed index earns its place through
the Actionable section (review-pending, amended-pending) and its
clickable links while browsing — things a folder listing cannot
give, however fine the shard. The report adds the same data on
demand with zero committed state; since the audit computes both
from the same pass, the report costs nothing extra. Both it is —
and the index is regenerated on every audit run, so it can never
go stale silently. The overdue lane moved out again (issue #527):
a committed, parity-pinned artifact cannot carry "today"-derived
content — the parity gate compares the bare run while the audit's
regen used the real date, so the two disagreed on the file's bytes
whenever metas were overdue. Overdue enumeration is report-only
(audit stdout, make rules-report).

Check: audit runs regenerate the INDEX and print the report; the
Actionable section matches the `reviewed:` field state.
