Pilot finding: many bullets span several lines, so a ref on the first
line lands mid-sentence or inside a code example — only the item's end
is always grammatical. Rule files (AGENTS.md and agent/*.md) are
always-on reading: every session pays for their length. A bullet
states the instruction plus at most a one-sentence mini-why — short
dated era-markers conform; length decides, not the presence of a
date. The evolution narrative (the iterations a rule went through)
is meta material: the review log IS that history, next to the
lifecycle data — the curation-and-verification section in
review-concept.md with its meta is the canonical split for where
history lives (its rationale length exceeds the mini-why cap; the
split is about history placement, not bullet length). Clarified
2026-11-17 at maintainer direction: the old no-dates wording read
stricter than the intent.

Check: rule sections state the current rule only (the
curation-and-verification split is the shape); a rule section
narrating superseded versions is a defect — iteration history
stays in the metas; one sentence naming what a form superseded is
an era-mention, narration starts at the second.
