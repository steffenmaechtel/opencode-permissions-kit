The 0.0.41 chain blurred the four recording roles — dispositions
front-ran into index rows and snapshot prose, and the resolution
became a retroactive reconstruction. The consequence: when the next
review starts from a summary (index row with SHAs) instead of the
per-finding ledger, the why of each disposition is already lost. The
generated INDEX is a summary by design (hand edits fail the parity
test), so only the resolution can be the authoritative ledger.

Check: each case folder carries a resolution.md whose rows cover the
chain's findings; INDEX rows stay generated.

separation (the 0.0.41 chain)".
