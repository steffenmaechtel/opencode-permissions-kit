The two dates genuinely diverge: where a fix reshaped an old bug
without closing it, the site's code age exceeds the reported
behavior's age. Concrete case (0.0.44a snapshot,
internal/reviews/0/0/1/4/pr-00142/review-a.md): finding V1's code
site exists since 0.0.19 (as a silent no-op), but the bug-form
bucket table lists V1 under "0.0.44 (created by the 0.0.43a/b fix
waves)" — the wave reshaped the old site into copy-without-move
without closing it. V2 (hole since 0.0.40, created by the F10 gate
fix) is the same shape. Collapsing the two into one date would hide
the reshape cases the regression-rate question needs.

Check: provenance tables in snapshot-scope review reports carry
both dates and rows where they differ (V1 in pr-00142: 0.0.19 code
vs 0.0.44 bug-form).
