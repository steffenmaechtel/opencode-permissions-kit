An upstream release on the review day (opencode 1.18.33) changed
login behavior under the suite; without the binary version and host
layout recorded in the snapshot, its results are uninterpretable
afterwards — a later reader cannot tell whether something was broken
or the run was against a different world. The environment block is
what turns a snapshot into reproducible evidence. On kit-managed
hosts that block has a probe constraint: the wrapper at
/usr/local/bin/opencode intercepts opencode --version for the agent
user — the probe dies at the sudoers gate (stdout empty, the refusal
on stderr; verified 2026-11-22) — so the sanctioned source is the
kit-managed binary itself,
/usr/local/lib/opencode-permissions-kit/bin/opencode --version,
whose output the agent user may read (maintainer-confirmed, issue
#750).

Check: snapshot headers carry opencode binary version and host
layout; anomalous runs attribute to recorded environment drift. On
kit-managed hosts the version names the kit-managed binary's probe
output, or the recorded degradation wording.

Source: internal/records/review-calibration.md, "Incidents behind the
hard rules".
