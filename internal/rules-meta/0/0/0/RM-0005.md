Empty input is not rare: `read` returns it at EOF, so any prompt
reached from a pipe or a closing stdin answers empty. A prompt that
re-asks or aborts on empty input would turn every non-interactive slip
into a failure. Mapping empty to the default makes the no-thought
answer the safe one — which only holds because the default itself is
chosen safely.

Check: `ui_confirm` / `prompt_yn` / the wrapper's `case` all map an
empty answer to the default; no shipped prompt loops or aborts on
empty input.
