The kit's yes/no prompts render from four implementations that
cannot share code — sourced ui.sh, install.sh's `ui_menu`,
uninstall.sh's standalone `prompt_yn`, opk's damaged-library
fallback. A second format (`(yes/no)`, `[yes|no]`, bare `Y/N`)
fragments cross-command recognition and re-opens the pre-unification
state the archived ux record closed. Choices beyond yes/no have an
existing answer — `ui_menu` with keyed entries — so a richer prompt
never needs a format mutation. Shape pins exist since the issue #187
wave (tests/unit/test-ui.sh, test-uninstall.sh, test-kit-cli.sh:
prompt shape on stderr + answer semantics); the marker-direction
decision (maintainer chat, 2026-10-16) dropped the `[?]` marker —
the canonical shape is the indented, marker-less `<question> [y/N]`.

Check: grep `files/` for `(yes/no)`, `[yes|no]`, `Y/N`, `[?]` — no
hits; multi-option prompts use `ui_menu`.

Source: internal/records/_archive/design/ux-improvement.md (archived
decisions); shape-pin gap: issue #187.
