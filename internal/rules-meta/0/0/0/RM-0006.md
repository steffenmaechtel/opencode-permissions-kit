Real answers arrive in mixed case (`Y`, `Yes`, `no`) and real
terminals deliver stray keys; both are ordinary input, not attacks.
The accepted set is exactly what opk's fallback `case` matches after
lowercasing — that fallback cannot source ui.sh, so the set must
stay small enough to inline in every implementation. Input outside
the set must not abort or re-ask: falling back to the default keeps
unattended runs moving without bypassing the deliberate default.
Answers are edge-trimmed before matching (#189 a W2): `read` without
`IFS=` strips leading/trailing whitespace, so a padded ` y` is an
explicit answer in every implementation (ui.sh's `_ui_read`, opk's
fallback, uninstall's `prompt_yn`) — not unknown input silently
falling to the default.

Check: the case arms cover y|yes|n|no (lowercased, edge-trimmed) in
every prompt implementation; every other answer resolves to the
default — pinned in tests/unit/test-ui.sh, test-uninstall.sh and
test-kit-cli.sh (padded-answer pins under both defaults).
