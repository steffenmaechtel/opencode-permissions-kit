A flat folder holding 100+ metas becomes an unnavigable wall in IDE
trees and file listings. Sharding by the first two ID digits caps
every folder at 1000 entries while keeping the location computable
from the token alone — no bookkeeping, no semantic mapping to
maintain, and a rule moving between files can never affect where its
meta lives. Migrated while the corpus was 13 files (a pure `git mv`),
because every later consumer — index, audit, bookmarks — would have
pinned the old paths.

Check: every meta file sits in the bucket matching its first two ID
digits.

Source: maintainer decision 2026-10-15 (flat concern → sharding).
