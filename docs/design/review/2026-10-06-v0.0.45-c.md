## HIGH/MED detail (as reported)

### S1 — `project_path_sane` accepts trailing-`/.` project roots

The dot-segment refusal (`install.sh:879`) is `*..*\|/./\|*/./*\|./*` — it only rejects *interior* dot segments. A trailing `/.` matches none of the arms, and the system-path blocklist (`:884-891`) has no `/var/*`/`/home/*` catch-all (deliberately — homes host projects). Verified empirically with the extracted function:

```
ACCEPT: /.            (norm=/.)
ACCEPT: /var/.        ACCEPT: /home/.     ACCEPT: /home/opencode/.
refuse: /srv/x/.      (only because /srv/* is blocklisted)
ACCEPT: //x           (leading double slash also passes — *//* is not in the pattern
                       either, although bin/opk's form filter refuses it)
```

`--projects /.` (no glob characters, so parse_args passes it) or the same string at the interactive prompt is accepted, written to projects.conf, and Step 5 (`install.sh:1665`) runs `fs_baseline_root` on it: as root, `chgrp <sharing-group> -R` + `chmod g+rw` + `setfacl` defaults over the entire filesystem (`/var/.` → /var/lib, /var/log, mysql; `/home/.` → every user's home including `.ssh`). `/home/opencode/.` additionally defeats the agent-home exclusion at `:895` (`"/home/opencode/." != "/home/opencode"`) — the exact directory the S4 exclusion exists to protect. Severity depends on the trigger: it needs the user to enter or pass a `/.`-form path — but the impact is a silent filesystem-wide group baseline as root, one keystroke away from the refused `/`. **Fix shape:** mirror the opk form filter (`*/.` and `*//*` arms — it already has both), plus a pin covering `/.`, `/var/.`, `/home/opencode/.`, `//x`.

### S2 — finalize's root `chown` on `manifest.conf` dereferences a planted symlink

`ddev_migrate_export`'s finalize (`sh/ddev-migrate.sh:494-510`) hands the dump dir to the agent (`chown -R "$dm_oc:$dm_ocg"`, then `chmod 750`), and the code's own comment (`:505-509`) correctly notes the dir is then agent-owned, no sticky — the agent can rename entries. What the wave missed, five lines later:

```sh
chown "root:$dm_ocg" "$DD_MIG_DUMP_DIR/manifest.conf" 2>/dev/null || true
```

`chown(2)` follows the final-component symlink (verified as root in a fresh ubuntu:24.04 container: `chown root:disk link` changed the *target's* group). The window opens at `:494` — the agent gets an inotify ATTRIB the moment the dir's owner changes, and has the duration of the two intervening `find … -exec` passes to unlink the root-owned manifest (dir owner may) and plant `manifest.conf -> /etc/shadow`. Root then assigns the sharing group to an arbitrary path; with `/etc/shadow` (mode 640) that is password hashes disclosed to the agent user — the exact contained principal the kit exists to contain. The two chmod `find`s at `:496-499` skip links (S5 is their race variant), so nothing protects the `:510` chown. **Fix shape (also closes S5):** do all root-side operand operations *before* the hand-over — chmod/chown the dumps and manifest while the dir is still root-owned and sticky (rename-plant impossible), then `chown -R` last; alternatively gate the operand on `[ ! -L ]` immediately before use *and* use `chown -h`-shaped non-dereferencing forms. Pin with a run-4-style planted-link harness that keeps the victim's group intact.

### C1/C2 — bounded `timeout` probes abort the installer silently (rc 124, zero output)

`install.sh:689` and `:1828` both use `_x=$(timeout 10 "$bin" --version 2>/dev/null \| head -1)` as a plain assignment. Reproduced under `bash -eu -o pipefail` (the documented runner, `:40-41`): a killed probe (rc 124) takes the pipeline status, errexit kills the script — no message, rc 124. At `:689` the surrounding comment explicitly promises "never abort … warn EARLY" for the wedged-binary scenario (issue #80) — the `ui_warn` at `:696` is reachable only when the binary *answers* with noise; the hang case (the one named) aborts. At `:1828` the abort lands post-provisioning (half install), and the "unparseable/empty — keep the previous stamp" arm is likewise only for answering binaries. Fix: the 0.0.45a S1 idiom ten lines up in the same file — `… \| head -1 \|\| true` inside the substitution (the os-release reads already do exactly this).
