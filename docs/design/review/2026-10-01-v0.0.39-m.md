## Code quality — bugs & robustness

| # | Sev | File(s) | Finding |
|---|-----|---------|---------|
| C1 | LOW | `files/opencode-permissions-kit-lib/bin/opencode-as-opencode:19-23` | The wrapper defined its colors unconditionally (no NO_COLOR / non-tty guard) — the last standalone script without the rule that ui.sh, uninstall.sh and setup-container-backend share (0.0.39e C10/C12): piped output leaked ANSI bytes, `NO_COLOR` was ignored. Fixed in `0a9734a`: colors resolve to real bytes via `printf` and go empty under NO_COLOR/non-tty (the single-quoted `'\033[…'` literals also made the wrapper depend on dash-echo escape interpretation — the conversion removes that portability wrinkle). |
| C2 | INFO | `files/install.sh:243-244` | The ui.sh-fallback comment overclaimed "keeps install.sh working if ui.sh is somehow missing" — the fallback defines the output helpers only; the interactive prompts (`ui_ask`/`ui_confirm`/`ui_menu`) live solely in ui.sh, so a ui.sh-less run proceeds only to its first prompt and dies there (set -e). The 0.0.39e C15 "comments now say so" claim did not hold for this one. Fixed in `0a9734a` (comment corrected). |
| C3 | INFO | `files/opencode-permissions-kit-lib/management/status.sh:8` | `set -u` only (no -e/pipefail) — defensible fail-soft for a read-only report (failing probes render as "unknown" rows) but undocumented as deliberate. Fixed in `0a9734a` (header comment, same class as uninstall.sh's documented no-set-e). |
