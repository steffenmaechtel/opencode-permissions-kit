## Follow-ups the implementation itself required

Exactly the class the review warned about ("or audited `set +u` windows",
0.0.39a C2) — recorded here as expected reading for the next review:

1. **Pipefail fallout** (`ef6edd0`): enabling pipefail un-masked two
   failure classes the old `tail`/`grep` consumers had been hiding.
   - Optional-file command substitutions (`sed` on a missing
     install.conf: `DDEV_EXPORTED_PRE`) killed the fresh-container
     install at Pre-flight — found by `make e2e` dying in step 2.
   - `update_install_conf_backend`'s braced group ended in a false
     `cond && echo` list: errexit exempts AND-list members, but pipefail
     turns the group's status into a pipeline failure — config.sh died
     AFTER successful podman provisioning, silently downgrading e2e
     section 12i to SKIP (21 checks lost, suite still "green"). Both
     fixed (`|| true` on optional reads, if-statements + `|| true` in
     the conf-rewrite pipelines).
2. **Upstream: opencode 1.18.33 device-login hang** (`ef6edd0`, test
   side): 1.18.33 (released the same day — the suite resolves latest and
   had first contact) survives SIGTERM during the console-login poll;
   reproduced against the raw binary with no kit code involved (1.18.32
   exits cleanly, rc 124). The wrapper login e2e now cannot hang: file
   redirect instead of a pipe, `timeout -k` SIGKILL, and a self-excluding
   `consol[e] login` pkill reap step. Worth an upstream report.

Final suite levels after the follow-ups: e2e 269/0 skipped,
e2e-rootless 47/0 skipped — identical to the pre-change baselines.
