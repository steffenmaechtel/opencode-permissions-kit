## Security

| # | Sev | File(s) | Finding |
|---|-----|---------|---------|
| S1 | **HIGH** | `management/uninstall.sh:388-389` | The ownership revert selects by `find "$root" \( -uid … -o -gid … \) -exec chown … {} +` without excluding symlinks — `chown` on a symlink operand FOLLOWS it, so an opencode-owned symlink planted inside a project makes the root-run uninstall chown an arbitrary target outside the project to `DEFAULT_USER:$UN_DEV_GROUP`. Breaks the kit's own operand-level `[ -L ]` discipline (fs-baseline, handover). Fix: `-type l` exclusion or `chown -h`-shaped no-follow semantics + regression test. (= Luna S1; confirmed. Missed by 0.0.42d — calibration note below.) |
| S2 | **MEDIUM** | `sh/ddev-handover.sh:243-277, 505-521` | Docroot validation is lexical only (`_ddev_docroot_sane`); the `[ -L ]` operand gates at :513/:520 reject only a symlink AT the settings-dir operand. An intermediate component (e.g. `docroot: web` with `web` a symlink out of the project, `.ddev/config.yaml` being agent-writable after a prior handover) passes both gates and the root-run `chown -R`/`chmod -R` at :519/:521 resolves through it — handing an arbitrary outside tree to the agent group. Fix: resolve the joined path and enforce project containment. (= Luna S2; confirmed.) |
