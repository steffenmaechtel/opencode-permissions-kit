| S1 | LOW | `files/install.sh:1710-1716`, `management/update.sh:627-642`, `management/status.sh:631` | Never-shadow guard drift for the xdg-open shim. Install refuses to deploy while ANY `command -v xdg-open` hits; update's heal/deploy branch and status's verdict probe only fixed paths (`/usr/local/bin`, `/usr/bin`). Two directions: (a) a real xdg-open outside the probed paths (e.g. `/usr/sbin`, `/snap/bin`) makes `opk update` deploy a shim that install would have refused — `/usr/local/bin` precedes them in the default PATH, so the shim silently shadows the real one; (b) a real xdg-open installed at `/usr/bin` after the kit keeps being shadowed until the next `opk update` heal (that heal works, update.sh:629-632, but the window is silent — the shim exits 0 where powershell.exe is unreachable, so GUI-open no-ops without a signal).
