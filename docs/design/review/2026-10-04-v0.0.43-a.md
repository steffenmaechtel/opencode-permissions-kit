| F1 | **MED** | `scripts/advisory-watch.sh:82-85` | The severity vocabulary (`low\|moderate\|high\|critical`) rejects GitHub's `medium` — the polled endpoint (`GET /repos/{owner}/{repo}/security-advisories`, line 26) defines severity as **`critical\|high\|medium\|low\|null`** (GitHub REST docs, verified against the live feed); `moderate` is the vocabulary of the *global* GHSA database, not this endpoint. Fix: accept `medium` and map it to `moderate` at the boundary — line 140 embeds `$SEVERITY` into an `ADVISORY_RECORDS` template whose shipped vocabulary (`sh/advisories.sh:24`) is `low\|moderate\|high\|critical`. |
| F2 | **MED** | `scripts/advisory-watch.sh:44-47,106` | Empty TSV fields collapse under tab-IFS `read`. Tab is POSIX IFS whitespace: consecutive tabs collapse, empty fields are dropped — `read` shifts every following column left (`PATCHED` receives the summary text), the shifted value fails the `*[!0-9.]*` charset check → skipped loudly → `die` → red CI, no issue. The guard itself works (precisely the column-shift case it exists for — no injection), but the advisory is never tracked. Intent conflict: `tests/unit/test-security-advisories.sh:288` asserts an *empty patched value is valid*; the `read` layer defeats that before the guard sees the data. The shipped DB avoids this class via non-whitespace `IFS='\|'`. Fix: emit a placeholder (e.g. `-`) for empty fields, or switch the TSV separator to a non-whitespace character. |

| F4 | **MED** | `bin/opencode-as-opencode:547` | Unguarded `cd "$SERVE_FALLBACK"` aborts `opencode serve` — the script runs `set -e` (line 17). The fallback was chosen because `cwd_probe` — running **as opencode** — reported it readable; nothing guarantees the *invoking developer* can traverse it. Realistic cases: `SERVE_FALLBACK` = `/home/opencode` (last resort, line 537) — install sets it `opencode:<group>` mode **2750** (install.sh:1796-1797) and adds the developer to the group (install.sh:950), but that membership only activates at the next login: an `opencode serve` from the same shell that ran the installer lacks the group → `cd` fails EACCES → `set -e` kills the wrapper **before the exec** → serve exits non-zero.
