## Findings detail

### D1 (LOW) — the prescribed "unknown row must not print" leg is missing, and three claims say it isn't

What 0.0.48c prescribed (its fix shape, verbatim): "the extracted gate
block against a fixture LIBDIR without `bin/opencode` must warn **and must
not print the 'unknown — probe failed' row**". What the wave implemented:
the gate warns — and then `ADV_VER` stays empty, so the render `else` at
`:274–279` fires anyway. Lead-verified twice (extracted bytes and a
full-file fixture run):

```
⚠  opencode binary missing or not executable — advisory check skipped (fix: sudo opk update)
   opencode version unknown — probe failed (run: sudo opk status)
```

Impact: the verdict is correct (warn counted, exit 2 in `--short`,
non-zero in full mode — the false-green core of C1 is closed at every
caller; security axis traced the counters through `ui.sh:130` past the
silent guard and the summary exit path). The residual is a contradictory
informational row whose advice loops (sudo re-renders the same two rows)
directly below the row that names the real fix — plus the claim failure:
the resolution C1 row, the README 0.0.48c row, and the immutable
`13dadca` message all state "only binary-present-but-probe-failed stays
the uncounted privilege-unknown". The pin gap is structural: the sed
extraction `/^    ADV_VER=""$/,/^    fi$/` captures exactly `:240–256`
(the first 4-space `fi`), so no assertion in the block can observe the
render branch, and repo-wide no other pin carries the property (the W3
static pins assert the row exists as plain `ui_kv`, agnostic to when it
prints).

**Severity ruling (lead, over the quality axis's MED):** MED in this
corpus requires the fix's core mechanism to fail somewhere that matters —
verdict, security, or reachability (`0.0.44e E1` dead branch, `0.0.46b W1`
unreachable loudness, `0.0.42f` containment siblings). Here the core
mechanism verifiably works at every caller privilege; what remains is a
rendered row plus bookkeeping claims — the exact shape rated LOW in
`0.0.47c C1` (working fix, pin gap) and `0.0.47c C2` (row claim false, no
pin). Downgraded to LOW with this trace; the quality axis's calibration
argument (false claim on the very axis the previous MED was found) is
recorded above. **Fix shape (small rider):** skip (or reword to
"advisory check skipped — binary missing") the unknown row in the
missing-binary shape — e.g. gate the render `else` on the same `[ -x ]`;
extend the behavioral pin to run the render block too and assert the
unknown row does NOT print for the missing-binary fixture (the 0.0.48c
prescribed property); correct the resolution C1 row and the README row;
note the immutable `13dadca` message C3-style.

### D3 (LOW, residual record) — corrupt-but-executable binary is the remaining false-green shape

The W3 rule (probe-failure ≡ privilege-unknown) keeps a *present and
executable but broken* binary invisible to the verdict: the probe yields
no version line, the uncounted unknown row prints, and a kit with no
other findings reports "All green"/exit 0 while the wrapper dies at the
first agent session. Reachable because `update.sh:940` replaces the
binary with a non-atomic in-place `sudo cp` (an update killed mid-copy
leaves a truncated 750 binary). This is the consciously dispositioned
W3/W8 boundary, disclosed in the resolution and scoped in cli.md — not a
defect of this wave (the wave's C1 fixed the *missing/unexecutable*
shape; this is the *present-but-broken* shape). The in-row advice
("run: sudo opk status") cannot resolve this shape either — the same L3
imprecision as D1's residual, one corner deeper. Recorded as the
candidate for a future wave: distinguish exec-failure from empty output
in the probe (or fingerprint the deployed binary), and make the binary
replacement atomic (temp + `mv`); no action owed in this chain.
