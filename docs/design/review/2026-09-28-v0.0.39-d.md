## Security / robustness

| # | Sev | File(s) | Finding |
|---|-----|---------|---------|
| S1 | **MEDIUM** | `management/config.sh` (projects_list) | The function ended in `[ "$num" -eq 0 ] && ui_detail "(none configured)"` — a false short-circuit as the function's LAST statement makes `projects_list` return 1, so under the wave's new `set -e` `opk config projects list` and `opk config status` exited 1 **whenever project roots were configured** (live-reproduced). Same errexit class as the wave's own GIT_FLAG_GIVEN fix, missed because it hides inside a function. |
| S2 | **MEDIUM** | `files/install.sh` (provisioning output), `management/config.sh` (backend switch ×2) | `echo "$_setup_out" \| grep -v '^OPENCODE_' \| sed …` unguarded: `grep -v` exits 1 when the setup output consists solely of `OPENCODE_` key lines, and pipefail turns that into an abort **right after successful backend provisioning** — the exact class the wave fixed in `update_install_conf_backend` (ef6edd0) but missed at these three display pipelines. |
| S3 | **MEDIUM** | `files/install.sh`, `management/update.sh` | `trap cleanup INT TERM` ran the cleanup but never **exited**: after SIGINT/SIGTERM the interrupted script resumed running — with its fetch tree and scratch files already deleted. Cross-confirmed independently by two agents (listed here once; the correctness agent's C1 row is the same finding). |
| S4 | LOW | `sh/ddev-hosts.sh` | The new hostname charset gate checked membership only — a leading hyphen (`-foo`) passed and reached `ddev hostname -foo 127.0.0.1` as an option-looking argv (quoted, no shell injection; underscore names are dropped entirely, which is correct for DNS names). |
| S5 | LOW | `files/install.sh`, `management/config.sh` | `_th="$(getent passwd "$SUDO_USER" … \| cut -d: -f6)"` — a stale/unknown SUDO_USER makes getent fail; pipefail turns the substitution into an abort where the old code continued with the (guarded) empty value. |
| S6 | LOW | `management/update.sh` (re-exec) | If the re-exec'd fetched update.sh dies on a parse error (corrupt-but-HTTP-200 fetch), dash may exit without running the EXIT trap, orphaning the root-owned `_FETCH_TREE` in /tmp. Unverified for bash (may fire the trap). Accepted residual: 0700/root-owned, bounded. |
| S7 | INFO | `tests/e2e/run.sh` | The login-cleanup `pkill -KILL -f "consol[e] login"` matches any process whose cmdline contains "console login" — within the e2e container nothing else does; scope is container-local by construction. Accepted. |
| S8 | INFO | (verification-positive) | cleanup() is set -u safe in dash+bash (`${VAR:-}` guards + upfront initializers); INT during a pipeline defers the trap to the pipeline's end in both shells; the exported `_FETCH_TREE` only travels parent → re-exec (sudo's env_reset scrubs it for sudo children); no other consumer found. |
