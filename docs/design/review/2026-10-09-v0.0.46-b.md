## Findings

### W1 (MED) — 0.0.46a F1's "loud" is unreachable on the caller F1 named: the hook swallows the helper's stderr

`sh/ddev-handover.sh:124-127` and `:171-172` send both new warnings to
stderr (mirroring the symlink gates), but the only caller that can actually
fail the write — `ddev config` → `_opk_devowned_flag`
(`sh/ddev-terminal.sh:298-300`) → `sudo -n -u opencode …
--opk-devowned-flag` — runs that sudo call as `… 2>/dev/null || true`, and
`bin/ddev-as-opencode` passes the streams through unchanged. The success
note is stdout and reaches the developer; **both new warnings (and the two
pre-existing symlink-gate warnings of the same function, 0.0.39g S2 /
0.0.39h F13) are discarded on the hook path.** Scenario: dev-owned mode on,
clone with dev-owned `0644 config.yaml` / `0755 .ddev` (the -a F1 case) —
after `ddev config` the developer gets no flag-specific note at all, exactly
the "never learns the project is still unflagged" state F1 complained about
(the lie is gone everywhere — that half is genuinely closed — and in this
clone edge ddev's own command has usually already failed visibly; the lost
information is the flag-specific guidance). Why MED and not LOW: the
disposition's headline claim ("failure modes … now loud and honest … never
go silent") is false at the finding's named entry point, and the pins are
structurally blind to it — the unit F1 pins call the function directly under
`2>&1`, e2e DD13 greps the success note from a merged-stream log. Per
review-concept's hard rule ("a disposition claim owes a behavioral test, not
prose") this is the house's fix-claim-false-at-path MED class (0.0.42f
W11–W15, 0.0.44d F1/F2 precedents); the behavioral impact itself stays at
-a F1's LOW. Fair provenance: the -a review's own fix shape prescribed the
stderr mirror — both the prescription and the fix missed the pre-existing
swallow (from `928e653`). Fix shapes: (a) drop `2>/dev/null` from the hook's
sudo call — `sudo -n`'s own failure text then surfaces on broken-sudoers
machines, which is signal, not noise; (b) route the helper's
`--opk-devowned-flag` mode diagnostics to stdout (`exec 2>&1` in that
branch), keeping stderr semantics for the root-run scans; or (c) stdout
warnings unconditionally. Available pin: a static assertion on the hook's
call shape (no stderr suppression on the `--opk-devowned-flag` invocation),
which discriminates jointly with the existing function-level warning pins.
Whatever the shape: close the class, not the site — all four swallowed
warnings of `ddev_devowned_flag`, not just the two new ones.

### W2 (INFO) — wording-accuracy corners of the new warnings (fix riding W1)

(a) The cat-branch message says "NOT written", but an ENOSPC-class failure
*after* a successful open can leave `config.yaml` truncated/partial while
cat returns non-zero — the truncation risk is pre-existing, the message
claim is new. (b) "(the next root-run scan retries)" is optimistic under the
issue-#112 stamps: a git-pull-restored upstream `config.yaml` (flag gone)
with a still-valid stamp is skipped by a plain `opk update` — that retry
needs `--refresh` or an explicit handover. Both are currently masked by W1
on the hook path; reword when closing W1.

### W3 (INFO) — F7's "other commands heal nothing" is a hair over-correct

Browser commands (`launch`/`mailpit`) on a *stopped* project heal via the
internal start at `ddev-terminal.sh:169-173` — a start did actually run, so
the parenthetical is defensible; recorded for precision only, no action owed
(sub-agent catch, lead-verified).

### W4 (INFO) — the F2 mode-on pin's sudo leg is live, not stubbed, on kit hosts

On a host with the NOPASSWD rule and an `opencode` user, the on-pin's
`/usr/bin/sudo -n` really executes the deployed helper against the /tmp
fixture (the gate probes are hermetic; the exec is not — sudo is not
stubbable by design). Verified harmless: the `mktemp -d` fixture is 0700
tester-owned, so the helper's own `[ -f ]` gate fails or at worst a flag
lands in scratch. The deviation is disclosed in the resolution; recorded so
the "hermetic" label is not over-read.

### W5 (INFO, pre-existing — out of wave scope, class-map entry)

`management/status.sh:433` interpolates a find-derived, agent-influenceable
path into a copy-paste `sudo … --opk-ensure-shared "$_st_d"` fix line: a
crafted parent-directory name (quote/backslash bytes in a path component
under a registered root — agent-writable trees) alters the command a
developer copies from the report. Pre-existing from the -a wave
(`14a5ba5`); only the neighboring display line changed in this wave.
Sub-agent catch, lead-verified against the code; same copy-paste-trust
family as the kit's other printed fix lines.
