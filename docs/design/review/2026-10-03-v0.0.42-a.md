**Verified clean (no findings):**

- **Data flow through the root-sourced helper is bounded end-to-end.**
  `git --version` output is constrained by `grep -m1 -oE
  '[0-9]+\.[0-9]+\.[0-9]+'` (git-check.sh:34) before anything downstream;
  `awk -v` receives a static program with the version only as
  split()/arithmetic input; ui.sh renders via plain `printf '%s'`. Live
  experiment with a fake `git` printing multi-line output containing
  `$(...)` and backslashes: only the dotted triple reached awk/ui/log.
- **set -e safety of the helper call sites**: probe pipeline ends in
  `head -1 \|\| true`; `command -v log && log …` sits in a non-final
  AND-arm (cannot trip errexit while log() stays rc 0 — the latent edge
  is Q2); update.sh's ui/log fallback stubs are defined before the
  git-check sourcing on all three run modes (repo checkout, streamed
  temp dir, installed-library re-exec).
- **status.sh fail-soft ordering** (set -u only): ui.sh is hard-required
  first (so `UI_GREEN`/`UI_YELLOW` are always defined), then the
  git-check block (LIBDIR first, checkout fallback), then the no-row
  stub — an old helper-less install drops the row, never crashes.
- **CI surface**: matrix values are the literal `[distro, latest]`,
  consumed only as `env E2E_GIT_CHANNEL`, never interpolated into
  `run:` text; the PPA add lives in the CI images only (no Dockerfile
  ships); the lib.sh tag suffix is a quoted assignment — hostile local
  env yields an invalid docker tag and a loud error, nothing quieter.
